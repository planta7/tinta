# Security and privacy model

## Assets to protect

Local document/source contents, embedded data, image bytes/metadata, filesystem authority, recovery copies, reader state and the integrity of the rendered explanation. Also protect host/browser availability from deliberately pathological input. The engine is a document processor, not a trusted-code execution environment.

## Untrusted inputs

Treat `.md`, `.tinta`, imported CSV/JSON, ZIP entries/manifests, image headers/bytes, answer snapshots, compiled-payload JSON, filenames, external link destinations and all iframe/worker messages as untrusted. Neither “created by this editor” nor a `.tinta` suffix establishes trust. Dependency code is trusted executable code only after locking/review; it is never selected by document content.

## Enforced boundaries

| Threat | Required controls | Required verification |
|---|---|---|
| Script injection | Bounded AST interpreter; no eval/Function; inert raw HTML; safe text/attributes; JSON script escaping; hash-based export CSP. | Source/payload `</script>`, HTML handlers, entity/scheme obfuscation and template strings cannot execute. |
| Data exfiltration | No remote resources/network API; blocked resource CSP; no author URL interpolation; explicit link navigation only. | Request interception shows no automatic external request on load, interactions, export or recovery. |
| Host access | Pure engine no fs/storage/network; sandboxed preview without same-origin; explicit file capabilities. | A preview cannot read parent storage, files, cookies or call unlisted host messages. |
| ZIP traversal/bomb | Entry allowlist, decoded path rules, no links, CRC/hash checks, incremental actual byte ceilings. | Traversal, duplicate/case collision, metadata lies, ZIP64, encryption, overexpansion fail before write. |
| Denial of service | Source/nesting/AST/row/mark limits, global operation budgets, worker watchdog, bounded output and diagnostic counts. | Fuzzing, adversarial depth, repeated views/charts and oversized images terminate predictably. |
| Misleading state | Candidate evaluation then atomic commit; immutable rows; export revision guard. | Failed calculations/chart domains never leave updated text with an old figure. |
| Accidental disclosure | Explicit interactive/static export difference; automatic local drafts with a persistent opt-out; no log content. | Hidden branches/images absent from static output when not visible; full-content warning for interactive. |
| Supply chain | Exact locks, provenance, license/audit gates, minimal modules, action SHA pins. | Build inventory and no editor dependencies in exports. |

## Renderer rules

Only the renderer creates known DOM elements/attributes. Untrusted Markdown HTML is never passed to `innerHTML`, `outerHTML`, `insertAdjacentHTML` or DOMParser as markup. Trusted export/sandbox shells may use static templates and a fixed serializer that escapes all variable data; security tests inspect the generated bytes. Renderer-owned SVG contains only the primitive allowlist: svg, g, path, line, rect, circle, text, title, desc, defs and clipPath; no foreignObject, use with external href, image, script, animation or URL-valued paint. All path/coordinate data originates from finite validated geometry. Generated IDs are implementation-owned and prefixed.

HTML output allowlist: article, section, p, h1–h6, ul, ol, li, blockquote, pre, code, em, strong, del, hr, br, a, img, figure, figcaption, table, caption, thead, tbody, tr, th, td, details, summary, label, input, select, option, button, output, div and span; additional shell tags are fixed by the artifact writer. No author arbitrary attributes, IDs or CSS. Control attributes are typed, URL attributes go through the destination policy, data text is escaped. `<input>` is used only for native approved controls/disabled Markdown checkboxes.

## Preview sandbox

The iframe sandbox tokens are exactly `allow-scripts allow-popups allow-popups-to-escape-sandbox`; omit allow-same-origin, forms, downloads, top-navigation, modals and pointer-lock. External links can leave the sandbox only by deliberate activation. The preview has an opaque origin and a CSP adapted to its trusted reader shell. Host save/import/export operations are outside the frame. It cannot ask the host to fetch a URL or resolve a filesystem path.

A host-created MessageChannel is transferred after a handshake checked with `event.source`; messages carry protocol version, document ID, channel capability and monotonic request/revision identifiers. Validate lengths/types/allowed discriminants before processing. Reject arbitrary extra commands and never execute message content. A port is closed when the document closes or recompiles into a new frame. `origin: null` by itself is never authentication. Cryptographic randomness is a host transport detail and never influences document calculations.

## Studio-specific CSP

The static application host permits its own same-origin JavaScript and styles, the exact trusted preview script hash and a Blob compiler worker, with `connect-src 'none'` and no remote fonts or images. Development HMR is a trusted loopback tooling exception. The standalone editor is trusted application code and needs CodeMirror's generated styles plus a Blob worker. Use `default-src 'none'; script-src 'sha256-<trusted-application-hash>' 'sha256-<trusted-preview-hash>'; style-src 'unsafe-inline'; img-src data: blob:; worker-src blob:; frame-src 'self' blob:; connect-src 'none'; font-src 'none'; object-src 'none'; base-uri 'none'; form-action 'none'` in the host. The exact trusted preview script hash is also present in the host policy because srcdoc inherits that policy in addition to its own CSP. Inline inert startup JSON blocks also receive their exact script hashes. The preview uses srcdoc with its own strict reader CSP plus the required opaque sandbox; validate actual srcdoc/file-origin behaviour in the browser matrix. No unsafe-eval or remote resource allowance is permitted. This exception applies to the editor host only, never to reader exports or author styling. Frame CSP, opaque-origin sandbox and safe AST rendering remain independent controls. Inline event attributes remain forbidden.

## File grants and recovery

No code traverses a disk tree because a document asks for it. CLI root grants come from explicit command arguments; browser grants come from file/directory pickers. Recovery belongs to the browser origin and may be accessible to local profile users; it is not encrypted-at-rest protection promised by the application. Do not describe it as a secure vault. The product never uploads or synchronizes those bytes. Raw image metadata is preserved; no privacy-cleaning guarantee.

## Adversarial verification

At least 10000 seeded property-generated inputs in scheduled/local security runs, plus fixed regressions for every discovered crash. Test no-hang boundaries at limit and limit+1. Ensure budget accounting covers nested expression work, sorting and all figures in one transaction. Malicious source must not cause an unhandled host exception or source loss. A rejected image/archive should be garbage-collectable and leave no orphan file/recovery mutation.

The final release requires a manual review of compiler/interpreter, raw-HTML handling, payload serialization, safe SVG, bundle extraction, file writes and the host bridge. Automated tests and CSP are layered protection, not a formal proof or external security certification. Do not label the project “audited” unless an actual audit has occurred and its scope is recorded.

## Vulnerability handling

Before the public repository has a configured private security-advisory channel, findings stay in a local private report to the owner; do not invent an email address. Once the owner enables GitHub private vulnerability reporting, SECURITY.md may point to that repository feature. Do not disclose exploit-bearing private document content in public issues or automatically transmit it.
