# VS Code Desktop host contract

This document specifies the local editor adapter. The repository provides a local development extension for text editing, source diagnostics, semantic highlighting, folding, contextual authoring and navigation. Interactive preview is available beside the native editor. Explicit local image roots, Markdown enrichment, in-memory source bundles and standalone HTML exports are available; the existing browser Studio remains separate. The language baseline is 1.0-draft.3, source format 1.0, IR `tinta-ir-1` and inner preview protocol `tinta-host-1`. Literal-only options, nonblank labels and metadata placement retain their existing semantics.

## Runtime and document scope

Use the local desktop extension host and native text editor. The minimum supported desktop version and compatibility-test runtime is VS Code 1.141.0, commit `2a59476c9bfcb90b3ddc372c36762471b7dfad1c`, with Electron 43.7.7 and embedded Node 24.21.0. Native workflow, Restricted Mode, performance and OS-offline checks cover macOS arm64, Linux arm64 and Windows x64 on this runtime. Other architectures and editor versions are not covered; browser results do not establish desktop support. Remote/SSH/container workspaces, virtual filesystems and vscode.dev are unsupported. Reject unsupported hosts before acquiring resources.

Associate only `.tinta` with `tinta` inside VS Code. Accept untitled buffers explicitly assigned that language. `.md` remains Markdown; enrichment creates a separate document. `.tinta.zip` is opened by an explicit archive command, never as text. Do not modify operating-system associations. Multi-root workspaces have independent document instances and resource grants; no workspace scanning, source imports or project resolution is permitted.

The language service receives supplied text/bytes through [editor DTOs](../contracts/editor-analysis.d.ts). It is pure and has no VS Code, LSP, DOM, filesystem, clocks or network dependencies. Recovering syntax supports partial queries but cannot establish validity. Only successful normal compilation and initial session evaluation establish `valid`; always destroy the temporary session. Preserve direct engine diagnostic ordering, codes and original spans. Do not put editor indexes in IR or inspect private engine maps. Ambiguous bindings have no fabricated destination; absent type information stays absent. Query offsets are original UTF-16 boundaries, not editor-normalized offsets.

## Source identity and fidelity

For example, original bytes `A\rB\n` become a uniform-EOL native editor buffer. Editing `A` and saving can also rewrite the separator after `B`; tracking native offsets alone cannot preserve that disk identity. This is a host limitation: the CLI, engine and source artifacts still accept UTF-8 BOM, LF, CRLF and CR, and invalid UTF-8 remains `E_ENCODING`. It requires no source-format or IR revision. Tests in `tests/vscode/host.mjs` cover unmodified and edited saves, BOM, line endings, astral positions and invalid UTF-8; the mapping probe checks original-byte ranges without treating collapsed newline positions as invertible.

A snapshot contains URI, fresh document-instance ID, native editor version, monotonic source revision, profile, validated UTF-8 bytes, exact decoded source, SHA-256 of those bytes and a map to native editor text. The hash includes BOM and original line endings. Copy mutable byte buffers when crossing boundaries and never expose writable internal snapshots. An editor version alone is not an identity; close/reopen, reload and Save As create fresh instances, revoke old file grants and invalidate pending results, panels and export candidates.

Opening a local file authorizes a bounded read of that exact file for strict UTF-8 verification, including in Restricted Mode. No parent directory grant is implied. Check path/descriptor identity before and after reading. Compare its mapped text with the same captured editor version; retry a changed version, reject a changed disk identity. A restored dirty buffer without an observed base is unverified: require a separately chosen UTF-8 copy before authoritative preview/export. Source diagnostics can still describe supplied editor text, but must identify its unverified status independently from disk/asset validity. A legitimate U+FFFD is valid; replacement-decoded invalid bytes are `E_ENCODING`. Never infer disk validity from `TextDocument.getText()`.

Unchanged files retain the validated original bytes. VS Code strips the initial BOM from its text model and normalizes lone CR and mixed line endings to its selected EOL. The host maps lines using source/editor start, content-end and next-line offsets; first source content starts after the BOM. Within line content, map code units exactly, including both units of astral characters. Compiler ranges map to zero-based LSP UTF-16 positions. BOM boundaries map to (0,0); boundaries inside a line ending clamp to the preceding line's content end; the boundary after the ending maps to the next line's (line,0). These collapsed positions are for presentation, not evidence of an invertible byte map. Navigation selects exact parser tokens, not substring matches.

Apply edits only to a matching document instance and previous native version. Validate nonoverlapping ranges against the previous editor text, map endpoints to source boundaries and apply in descending order. Retain untouched source segments and BOM, insert the event's exact text, strictly encode and recompute the map/hash. Reject invalid scalar text, overlapping ranges, surrogate splits, version gaps and unexpected full-buffer transformations. No stale edit is silently rebased. Native undo/redo are new versioned change events.

VS Code preserves bytes on an unmodified save, but a subsequent native save of an edited lone-CR or mixed-EOL file rewrites untouched line endings. Accordingly, these files may be analyzed and previewed unchanged; edits require explicit conversion to a **separate UTF-8/LF copy** before enabling tinta preview/export. Preserve the original document and show the conversion before creating the new buffer. No automatic normalization or overwrite is permitted. Native VS Code Save is outside tinta's byte-preservation guarantee; the extension must explain this limitation when such a document is first encountered. This policy also applies to dirty restored buffers whose original bytes cannot be verified.

Explicit native encoding/EOL changes invalidate the mapping and pending exports. After a native save, bounded reread and strict validation must match the expected bytes before reestablishing a snapshot; a mismatch is an explicit source-fidelity failure, never a successful export of a guessed revision. Reopen/reload rechecks disk bytes. Save As uses the new URI/instance and fresh grants. New untitled and explicit conversion copies use UTF-8 without BOM and LF. Native save hooks must not silently repair, cancel or overwrite user text.

Preview, unsaved export and its answer snapshot use exactly the same verified bytes, hash and revision. Current-answer export also matches session and asset revisions. Recheck all identities immediately before output commit; a changed source, resource grant or answer revision cancels the candidate.

## Files and Workspace Trust

The shared Node file adapter is the sole filesystem boundary for CLI and editor commands. Preserve existing bounded reads, symlink refusal, real-path containment, descriptor identity checks, cancellation cleanup, atomic writes and overwrite policy. Grant an exact input file, explicit image root or exact output target; never derive a grant from a source URI string, a protocol message or Workspace Trust. A document's parent directory is not an automatic image root. Untitled buffers need a chosen root to resolve relative images. Grants belong to a document instance and are revoked on closure, trust loss and identity changes.

Restricted Mode permits text analysis and preview with supplied in-memory assets, plus the exact opened-source read above. Resource-root selection/reads, bundle opening and all extension file-producing commands require a trusted workspace **and** explicit file/root selection. Enforce this in handlers as well as UI. Trust loss cancels pending IO and drops granted assets. Native editor saves are VS Code operations, not extension output commands. Core services never discover files. The LSP process cannot read author assets or run workspace-selected tools.

## Preview transport

The [outer bridge](../contracts/vscode-webview.d.ts) uses `tinta-vscode-1`, separate from `tinta-host-1`. Each panel has a fresh identity and at least 128 random bits of capability, injected only into trusted outer bootstrap code. Keep `acquireVsCodeApi()` in a closure and disable command URIs. Restrict `localResourceRoots` to packaged trusted resources (empty for fully inline bundles); never include document/workspace roots. No filesystem handles or path-read capabilities enter the browser. Source URIs and relative asset lookup keys convey identity only, never read authority. Do not resolve them or log them. Supply validated raster bytes only.

The inner iframe uses exactly `allow-scripts allow-popups allow-popups-to-escape-sandbox`, with no same-origin permission. Use the existing preview runtime and validate `event.source` for its exact hello before transferring the MessageChannel. A `null` origin alone is not authentication. Validate the inner protocol independently. The trusted outer page does not forward arbitrary iframe messages to the extension.

Both directions of the outer bridge reject unknown keys/discriminants, wrong protocol, panel/capability/document identities, non-safe integers, invalid hashes and over-limit payloads before dispatch. Extension request IDs increase; replies echo an outstanding request ID. `ready` uses ID zero once after bootstrap. Reader-originated state notifications reuse the last applied request ID and strictly increase session revision; only a reply to an outstanding get-state request may repeat the current session revision. IDs/versions/revisions are nonnegative safe integers (native editor version is positive). Panel/document IDs are 32 lowercase hex characters, capabilities at least 32 and at most 128 lowercase hex characters, and hashes exactly 64. URIs are bounded to 4096 UTF-16 units. Reject identities outside these bounds. Ignore well-formed superseded replies; malformed or unauthorized messages dispose the bridge with `E_PROTOCOL`. Fresh load may advance source revision only for the panel's bound document. Decode incoming programs with `decodeProgram`; types and schema shape alone do not authorize IR. Require load identity URI/profile/hash to match the decoded program. Outer asset bytes use canonical padded base64 with no whitespace; bound encoded length before decoding, then check decoded per-asset and total byte limits, SHA-256, MIME and safe lookup aliases using existing artifact validation. Convert to the existing Asset byte arrays only after validation; do not change the inner ABI. Validate controls with the existing runtime rules. No message requests commands, URLs, paths, saves, clipboard or storage.

The outer CSP denies all by default, permits only exact trusted script hashes, trusted styles, data/blob raster images and its own srcdoc frame. It denies connections, objects, base changes, forms and workers. Include the inner script hash in the outer CSP because srcdoc inherits it. The inner shell retains its own stricter CSP. No unsafe-eval, arbitrary inline scripts or remote scripts. The compatibility probe includes only a fixed test instrumentation hash; it is not part of the product policy. Dispose listeners/ports/sessions on closure or webview reconstruction. Recreated panels start from authored defaults; do not persist reader answers in VS Code recovery state.

## Scheduling, bounds and failures

Use the registry's 200 ms debounce and 3000 ms worker watchdog. Analysis executes in a terminable bundled ESM worker, never synchronously in the extension host. Keep the supervisor responsive, terminate stalled work and recreate the worker; cancellation messages alone cannot interrupt synchronous compilation. Explicit Check bypasses debounce. Coalesce obsolete edits and reject late replies.

Host limits are separate from language ceilings: at most 8 resident analysis snapshots, one active analysis worker and one pending request per document; at most 32 pending document identities. Evict inactive caches first. If all slots are active, report host capacity and retain the buffer for retry; never truncate source or falsely mark it valid. At most 4 live preview panels. Cap outer messages at 64 MiB UTF-8 JSON and 100000 traversed objects, with nesting at most 128; also enforce every stricter source/IR/asset/diagnostic registry limit. Reject a valid document whose transport exceeds capacity explicitly, without claiming a language error. Cached byte budgets: 32 MiB source, 128 MiB analysis DTOs and 100 MiB unique preview assets; release caches/ports on close.

Performance targets on the pinned runtime: host event-loop p95 delay below 50 ms while analyzing, no single delay above 100 ms; terminate within 1000 ms after watchdog expiry; cached completion p95 below 50 ms; small (10 KiB), medium (100 KiB) and large (1 MiB) source analysis p95 below 200/500/2000 ms respectively, excluding debounce. Use 30 warmed samples per size, 8-document rapid-edit runs and 100 open/close cycles. Post-GC retained heap growth after cycles must be at most 32 MiB; combined extension/server/worker RSS target is 512 MiB above an idle profile. These are host targets, not measured language performance guarantees. Language limits and coverage requirements apply independently of these performance targets.

Installed timing measurements use [conditional confirmation](07_VERIFICATION.md#native-timing-confirmation). A passing scenario runs once. If an analysis size, cached completion or host responsiveness measurement exceeds its timing budget, perform exactly two additional complete measurements of that scenario in the same installed profile, with the same corpus, warmup, sample count and resident-memory collection. Keep the first result and every confirmation. One budget failure out of three is `UNSTABLE`: emit a warning and continue CI. Two or three budget failures block CI. Host responsiveness is measured over all three analysis sizes, cached completion and the rapid-edit workload; its p95 and maximum are assessed together for each attempt. Functional errors, watchdogs, invalid/incomplete measurements and memory limits always block; they are not retried by this policy. Confirmation does not replace individual slow samples or turn an unstable result into a performance guarantee.

Pending/invalid source disables export; retain the last valid preview with a stale label and disabled controls. A first invalid document has an error view. Initial-evaluation failure is invalid source for preview; a rejected reader control candidate rolls back without making source invalid. Unexpected host exceptions expose an opaque incident ID, no source or stack trace in UI/logs. No telemetry. Asset status remains separate from source validity.

## Compatibility probe

With the pinned repository toolchain, run `pnpm build`, then `node scripts/probe-vscode.mjs <desktop-executable> <fresh-temporary-directory>`. The probe uses an isolated profile, supplied fixture files and the built existing preview; it is not an installed extension or an end-to-end authoring workflow. Its JSON result records native source/save behavior, embedded runtime versions, ESM compilation, watchdog termination/restart and nested sandbox observations. It fails if VS Code does not run the tests or return the expected report. The probe does not establish Linux/Windows support, full UI responsiveness, Restricted Mode command enforcement, or full performance targets.

See the official [webview guide](https://code.visualstudio.com/api/extension-guides/webview), [Workspace Trust guide](https://code.visualstudio.com/api/extension-guides/workspace-trust) and [Extension Host guide](https://code.visualstudio.com/api/advanced-topics/extension-host) for host APIs. File and sandbox authority is constrained further by this contract.

## Portable language analysis API

`@tinta-lang/language-service` implements supplied-source analysis independently of a native host. Call `analyze(input, version, options?)`, where `input` is the normal `SourceInput` and `version` supplies a 32-character lowercase hexadecimal `documentInstance`, a positive safe-integer `editorVersion` and a nonnegative safe-integer `sourceRevision`. The result contains an immutable `AnalysisSnapshot`, or fails with the direct compiler diagnostics when encoding or parser resource limits prevent a snapshot. Invalid host identity arguments throw `TypeError`. The service computes the source hash from the exact supplied UTF-8 bytes, including BOM and line endings; it does not verify where those bytes came from or grant file access.

Snapshots contain diagnostics, exact lexical tokens, headings and declarations, types established by successful binding, and global references established by successful compilation. Compilation success followed by initial-evaluation failure produces an invalid snapshot with semantic information. Syntax recovery produces a partial, invalid snapshot; declarations remain available, but inferred types and bound-reference destinations are omitted. This conservative policy avoids inventing destinations in ambiguous or malformed programs. Empty-list types are represented as `list` with scalar `never`, matching the expression specification. Editor facts are separate from ProgramIR.

`completion(snapshot, sourceOffset)` returns a parser-owned replacement range, a context kind and candidate names or literals. `help` returns plain text and built-in signatures. `definition` and `references` return exact global-identifier spans; columns have token ranges and completion support, but column navigation is unavailable. Offsets are original UTF-16 offsets. Out-of-range completion offsets throw `RangeError`. Markdown mode has headings but no active tinta tokens or completion. Literal code, comments, image text and destinations remain inactive in both profiles. These APIs do not insert text, rename symbols, register editor providers or produce trusted Markdown.

The catalog derives directive names, option keys and registered names from the syntax implementation; signatures and concise help are checked against the language specification. Completion supplies lexical context and conservative local candidates. Full authoring-provider behavior, including insertion edits and contextual suggestion ranking, belongs to the native adapter. Parsed data headers can support column suggestions while another region is invalid; schemas of invalid views are not inferred. A weak parser cache is only an optimization: copied snapshot DTOs are queried by reparsing their exact text. Query work remains bounded by the source and grammar limits; no incremental-parsing or native latency guarantee is implied.

For DOM-free browser workers, bundle with neutral resolution or the dependency `worker` export condition, as the existing Studio worker does. The locked Markdown entity decoder has a separate `browser` export that uses the DOM; selecting that export is incompatible with a DOM-free worker. The portable bundle test executes the neutral bundle without DOM, filesystem, timers or network globals. Native Node ESM uses the default portable dependency exports.

## Native editing and source diagnostics

Build all trusted runtime outputs with `pnpm build`; use `pnpm build:vscode` for subsequent native-adapter rebuilds. Open `apps/vscode` as an Extension Development Path in the pinned desktop runtime. Run `pnpm package:vscode` to create the explicitly allowlisted local development VSIX under `build/vscode/`; see the [offline quickstart](14_VSCODE_QUICKSTART.md). Release archives and extension identifiers are described in [software distribution](15_DISTRIBUTION.md). Bundles include the language client, IPC server and terminable analysis worker. No global CLI, workspace-selected executable, listening port or external Node installation is used. The upstream CommonJS LSP SDK has a fixed Node `createRequire` shim in its ESM host bundles; portable packages remain ESM and author text never selects modules.

Only `.tinta` is associated with the language. Untitled documents can explicitly select tinta. The fallback TextMate grammar uses the built-in Markdown grammar and intentionally adds no approximate tinta recognition; parser-owned semantic tokens supply tinta highlighting after analysis. Markdown files remain Markdown. Comment toggling uses HTML comments. Matching brackets and two-space defaults retain indentation detection and existing tabs. Automatic indentation keeps the current physical indentation rather than indenting tinta block bodies. Folding covers matched parser-owned tinta blocks and heading sections; unmatched recovered blocks do not acquire fabricated closing ranges.

The native adapter currently analyzes supplied editor text only. Its status tooltip explicitly reports disk encoding as unverified and assets as not checked. “Source valid” means that the current native text compiles and its authored initial state evaluates successfully; it does not establish original disk bytes, asset availability or export readiness. It performs no source-file or asset reads. The preview independently acquires strict original bytes, maps observed edits and offers an explicit separate UTF-8/LF copy. File commands consume this same verified source model for unsaved exports. Native saves remain VS Code operations, with the native normalization limitations already described.

`tinta: Check` bypasses the editing debounce. Normal changes use full UTF-16 synchronization, bounded by the source byte limit before transport. Diagnostics retain compiler codes, messages and related locations. Oversized source is rejected explicitly and never analyzed as truncated text. Source errors clear when repaired; closing the final text tab clears diagnostics and cached analysis even when VS Code retains its internal model. Reopening that model creates a fresh analysis instance. A full host-capacity condition retains the editor buffer and offers Check to retry after other documents close.

The server owns one worker, coalesces pending edits and terminates superseded or timed-out work before starting another worker. Concurrent symbol requests for the same document version share the in-flight result; an edit or close invalidates all callers. It ignores replies from retired workers and mismatched document instances/versions. Worker crashes produce opaque incident IDs and the next request starts a new worker. The client suppresses SDK payload/trace logging, including source text and paths; its error output contains only a fresh incident ID. Restricted Mode supports this supplied-text analysis without granting a directory or creating files.

Run `pnpm test:vscode:unit` for adapter, supervisor and protocol coverage. Run `node scripts/test-vscode-editing.mjs <desktop-executable> <fresh-temporary-directory>` after building for real Extension Host checks of typing, undo/redo, document lifecycle, Unicode locations, literal contexts, folding and worker termination/restart. The native runner uses an isolated profile and requires an actual result file; a process exit alone is insufficient. Linux/Windows behavior and the broader host performance targets remain unmeasured by the macOS native run.

## Contextual authoring and navigation

Native completion uses parser-owned contexts and replacement spans. tinta's language defaults turn off word-based fallback suggestions, which otherwise propose unrelated words even inside literal fences; users may override that native preference. Type `@` at physical column 1 for legal directives; root declarations and metadata are omitted where their placement would be illegal. Option completion omits used keys and chart-incompatible keys. Literal-only properties offer literals, and chart selection offers bare slider/choice names compatible with a known x column type. Source operands offer tables/views; row expressions offer their source columns. Aggregate column arguments offer quoted numeric columns. Function completion inserts a complete example call unless an opening parenthesis already follows; aggregate examples use a known local numeric column. The pure `functionExample(snapshot, name)` helper returns these call examples without changing source.

Suggestions remain editing assistance: surrounding errors, expression types and runtime domains still require normal validation.

Items labelled “example” insert complete plain-text examples with nonblank labels/summaries and unused binding names. At root, table/view/chart examples can include a small data declaration. Metadata examples appear only before content and when no other metadata exists. Examples do not reindent the document or insert executable snippet commands.

Hover shows definitions, available types, built-in signatures and option help. Signature help follows nested and unfinished calls, including their active argument and a concise example. Both use plain text; authored content cannot activate raw HTML or trusted command links. No live reader values are shown. The portable `signatureHelp(snapshot, sourceOffset)` query returns a plain-text label, zero-based argument index and example, or no result outside a known call.

The outline lists headings and declarations. Go to Definition and Find References use exact, document-local bound identifier spans. Prose, strings, fences and unrelated column names do not become references. Ambiguous or partially compiled programs have no navigation destination; safe local help and syntax-based column completion remain available. Column navigation is not provided, including view-column provenance.

Authoring queries execute in the same terminable worker as analysis and bypass the editing debounce. One pending query per document replaces an older query; edits, closure, worker failure and watchdog expiry release waiting requests without stale edits or destinations. The worker reuses its most recent matching analysis when available. Queries acquire no filesystem, network, command or preview authority. Native latency and cross-platform behavior require their own measurements; the editing test command above exercises these providers in the actual desktop host.

## Outer envelope validation API

`@tinta-lang/types/webview` provides bounded JSON envelope validators for the separate `tinta-vscode-1` transport, plus source identity comparisons. Validation rejects unexpected keys, unsupported discriminants, non-JSON values, accessors, cycles and over-limit trees before inspecting message fields. It checks source identities, control shapes, diagnostic locations and encoded asset envelopes. These functions do not establish panel authorization, freshness, program validity or raster validity. A receiver must separately bind the capability and document, track request/session revisions, use `decodeProgram`, and validate decoded asset bytes and lookup aliases before dispatch. The native adapter binds these envelopes to its panel and verified document instance before dispatch.

## Interactive native preview

The native editor title exposes **tinta: Show Source**, **tinta: Open Preview** and **tinta: Show Preview** with labeled icon tooltips for local and untitled tinta documents and tinta preview panels. Source brings the bound native buffer into its source editor group and hides the preview there. Open Preview shows source and preview in adjacent groups. Show Preview places the preview in the source group while retaining the pinned source tab, including unsaved edits. Menu resources resolve only already-open documents; preview actions select their bound document rather than another group's text editor. These actions do not close source tabs or grant file or webview capabilities. Markdown editors keep their existing native controls.

Use **tinta: Open Preview** for a local tinta document. Preview uses the current verified source, including unsaved mapped edits, in the supervised analysis worker. The outer webview validates and decodes its program before loading the shared opaque reader runtime. Four panels may remain open, each bound to one native document instance. Changing editor focus does not reset answers. Closing the source tab closes its preview and revokes the instance. A hidden webview reconstructed on return starts from authored defaults with a fresh capability; no answers enter VS Code recovery storage.

Original files are read only through `@tinta-lang/local-files`'s `readOpenedSource(path)`. This API accepts the exact opened document selected by the native host, checks regular-file identity and bounded reads, and supplies bytes without granting its parent directory. That entry point grants no asset reads, directory traversal or writes. Separate explicit-root and output APIs in the same package serve both CLI and native file commands. Source diagnostics remain independently useful when bytes cannot be verified. A restored dirty buffer, invalid encoding, an unobserved revision or edited mixed/lone-CR source cannot enable preview. **tinta: Create UTF-8/LF Copy for Preview** explains normalization and requires explicit confirmation before opening a separate document from current editor text. The original remains unchanged; a copy cannot reconstruct invalid bytes already replaced by native decoding.

Pending and invalid source disable the last valid reader and retain an explicit stale banner. An initially invalid source has an error status with no rendered document. Corrected source reconciles answers by control name, kind, ordered domain and authored initial; a failed retained candidate falls back atomically to all authored defaults. An expandable note lists reset answers. Successful source replacement resets reader presentation state; reader-only actions preserve their documented presentation state. Invalid reader actions roll back without invalidating source. Select an explicit image root or open a validated source bundle to supply reader images. Missing images never fall back to remote resources.

The outer runtime accepts supplied, validated raster bytes through the transport but cannot request paths, commands, URLs, saves, clipboard or storage. Its resource roots are empty and its CSP includes only exact trusted script/style hashes, data/blob images and its own opaque srcdoc frame. The reader retains the existing sandbox tokens and separate `tinta-host-1` handshake. Both layers dispose listeners, sessions and ports on closure. The document surface retains the reader's high-contrast light paper; surrounding status uses VS Code theme colors and focus indicators.

Run `node scripts/test-vscode-preview.mjs <desktop-executable> <fresh-temporary-directory>` for native controller/webview scenarios. Its isolated test bundle adds an explicit observation script and corresponding CSP hash; neither the test channel nor its extra hash enters product bundles. `pnpm test:vscode:browser` exercises the outer bridge with the shared reader and collects separate browser coverage. The native editing suite also exercises the product activation, preview command and supervised LSP compilation path. External-link tests intercept navigation after deliberate activation; they do not claim to verify the operating system's external browser.


## Local file commands

**tinta: Select Image Root** grants one local directory to the current document instance and checks all referenced images. **tinta: Refresh Images** rereads that explicit grant. Reads are bounded and reject forbidden paths, symlinks and non-raster input. Each completed selection or refresh replaces the in-memory store atomically with validated images, increments its resource revision and updates any preview. Unavailable or forbidden images produce explicit warnings and placeholders; their absence blocks only exports that require them. Root, IO or aggregate-limit failures retain the previous store. Source validity remains independent of image availability. Untitled documents have no implicit image root, and workspace membership never supplies one.

**tinta: Reset Reading** restores authored defaults in the matching valid preview without editing source. It also resets figure presentation. **tinta: Enrich Markdown** opens a read-only comparison of the current native Markdown text and the proposed collision-aware transformation. Only **Create Separate Document** opens a distinct untitled `.tinta` document. This explicit copy uses the text visible in the native editor; it does not recover bytes lost through native decoding or normalization. The original Markdown and its language mode stay unchanged. Ordinary saves remain native VS Code operations.

**tinta: Open Source Bundle** reads an explicitly selected archive, validates the complete bundle in a terminable worker and opens its source as a distinct untitled `.tinta` document. It retains validated image bytes in memory. It does not extract a directory, install a ZIP filesystem or replace an existing buffer. **tinta: Save Source Bundle** writes a canonical portable copy using authored defaults and rebased image destinations; it never writes current answers into source.

**tinta: Export Interactive HTML** and **tinta: Export Static HTML** explicitly ask for authored initial answers or current preview answers, then disclose the corresponding content/privacy boundary. Initial answers do not require an open preview. Current answers require a matching enabled preview, source hash, document instance, session revision and resource revision. Interactive output contains complete source, all data and hidden content; static output contains the resolved visible presentation and its images. Both may retain image metadata. Static export does not require images exclusively inside false conditions. The existing artifact writer produces offline standalone output with its existing CSP and safe renderer.

All extension file commands require Workspace Trust in both command enablement and handlers. Every input/root/output comes from an explicit native selection or the selected document. Trust is rechecked across asynchronous boundaries and immediately before committing output; a trust monitor cancels work and clears grants if trust is lost without host restart. Closure, new source identity and extension disposal revoke grants. At most one file operation runs at a time. Its dedicated fixed artifact worker uses the 3000 ms watchdog, terminates on cancellation/failure and never receives a filesystem capability. No shell, workspace-selected executable or network service is used.

Exports capture exact verified unsaved source and immutable selected image bytes. Disk-backed assets are checked against the selected/refreshed store before and after generation; changes require Refresh Images. Source, answer and resource revisions are checked again after staging, immediately before the atomic commit. A selected existing output needs explicit replacement confirmation and must retain its identity and metadata throughout generation. A competing new target fails without replacement. Output cannot alias source, originating Markdown/archive or selected images. Cancel, validation errors and stale revisions discard temporary output and preserve prior files. Final messages distinguish a completed atomic write from a cancelled operation.

The shared adapter exposes `readBounded`, `assertAssetRoot`, `readAssets`, `resolveAssets`, `identity`, `assertOutput`, `atomicWrite` and `unpackTree`; callers supply explicit paths and limits. `atomicWrite` accepts an optional synchronous revision guard and captured output identity for native commands. The CLI reuses the same implementation without changing argument grammar, JSON envelopes or exit codes. For CI, use the existing `tinta check document.tinta --json` source check or `tinta check document.tinta --with-assets --asset-root ./images --json`; see the [CLI contract](06_CLI.md). No lint, batch scan or watch service is added.

After `pnpm build`, run `node scripts/test-vscode-files.mjs <desktop-executable> <fresh-temporary-directory>` for native file/preview workflows and add `--restricted` for actual Restricted Mode handler tests. The harness scripts dialog choices while using real native documents, commands, diff views, workers, webviews and disk IO. It does not establish OS-picker usability, native Windows/Linux behavior or VSIX installation. Extension packaging remains separate from these development commands.
