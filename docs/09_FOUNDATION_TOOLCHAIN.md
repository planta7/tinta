# Foundation toolchain

Use Node 24.21.0 and pnpm 10.34.6. Install with `pnpm install --frozen-lockfile`, then install the pinned browser builds with `pnpm exec playwright install chromium firefox webkit`. Linux CI also uses `--with-deps`. Run `pnpm verify` (or `pnpm verify --suite infrastructure`) from the repository root. The verification command needs npm advisory endpoint access; an unavailable endpoint fails the gate.

The workspace implements parsing, typed evaluation, safe reading, chart geometry, local artifacts, command-line operations and the local editor. `pnpm verify --suite editing` selects the aggregate implemented gate, including unit coverage, conformance, all three browser engines, source bundles, actual file-origin exports and Studio workflows. The `parsing`, `semantics`, `reading`, `charting` and `artifacts` aggregates remain available; unknown capabilities fail explicitly. No command reads private progress records.

`pnpm build` emits ESM declarations/modules, a reader IIFE and stylesheet, the compiler worker and a complete standalone `build/tinta-studio.html`. Studio embeds trusted worker and opaque-preview runtimes, four source examples, and dependency notices. It requires no server or external chunks when opened through `file://`. The build also installs the identical HTML under `packages/cli/assets/` for `tinta studio`; a missing artifact still produces an explicit installation error. Vite's development build is separately emitted under `build/dev-studio/`; it is not the standalone artifact. Vite development/preview binds to loopback. Only esbuild's dependency build script is permitted during installation.

`dependencies.json` records direct official npm metadata selected under the approved release lines. `lock-inventory.json` records official metadata and integrity for every locked package, including optional platform packages. `node.json` pins the baseline archive checked on macOS arm64. `browsers.json` pins Playwright's browser revisions and platform overrides. `actions.json` records official action tag resolution and definition inspection. The transitive integrity lock is `pnpm-lock.yaml`.

`pnpm check:licenses` verifies the complete locked license inventory and that all installed notices are preserved in `THIRD_PARTY_NOTICES.txt`. The notices include development tools, not just product dependencies. To regenerate after an authorized dependency change, run `pnpm check:licenses --write` and review the result. Platform-specific binaries use their matching parent project's license text; the complete set of platform names is retained in the inventory. A platform may install a subset without removing other platforms' notices.

Reviewed notice sources: esbuild and rolldown native packages use the same-version parent licenses; lightningcss bindings use the matching lightningcss license. esrecurse and imurmurhash include full notices in their READMEs. natural-compare's README supplies its copyright and MIT designation; the standard MIT text is reproduced with that attribution. `@humanfs/types` declares Apache-2.0 in its manifest/README and uses the humanfs core project's license. These are unchanged third-party packages. MPL-2.0 dependencies (axe tools and lightningcss) are confined to test/build tooling; the checker rejects new MPL package identities for review. BlueOak-1.0.0 text from minimatch is included alongside MIT, ISC, BSD and Apache notices. No third-party license is replaced by the repository's MIT license.

Infrastructure coverage applies to the architecture scanner, capability selection and packaging primitives, with 85% statements/lines/functions and 80% branches. Build orchestration, inventory command-line scripts and configuration are exercised by their explicit aggregate commands. Empty product modules and type-only contracts do not count as runtime coverage. Product coverage thresholds remain as specified in the verification contract.

CI performs verification only on pull requests and pushes to the repository's configured default branch. It has read-only repository permissions, does not retain checkout credentials, and performs no deployment, package publication or artifact upload. Hosted CI execution and manual device acceptance are separate from local automated results.

## Native browser verification

`pnpm verify` runs Chromium, Firefox and WebKit together through Playwright on the host. To run just these infrastructure tests after building, use `pnpm test:browser:infrastructure`.

Browser tests import `test` and `expect` from `tests/browser/fixtures.mjs`. The shared fixture gives each Firefox worker its own temporary application-data directories through `MOZ_APP_DATA` and `MOZ_LOCAL_APP_DATA`, in addition to Playwright's temporary profile. These directories are removed after the browser closes, including when a test fails. An abruptly killed process can leave temporary directories for the operating system to clean up. Chromium and WebKit use their normal Playwright launch options.

This isolation avoids Firefox's startup access to personal browser data, which can fail under macOS app-data protection even when a temporary profile is supplied. See [Mozilla's profile startup issue](https://bugzilla.mozilla.org/show_bug.cgi?id=2069536). It uses the unchanged pinned browser build and does not require additional privacy permissions or changes to browser sandboxing. Browser binaries remain in Playwright's default cache, or the location explicitly selected by `PLAYWRIGHT_BROWSERS_PATH`; test data lives under the operating system's temporary directory.

Activate Node 24.21.0 in the invoking shell before running pnpm. The `.nvmrc` and `.node-version` files declare the version but do not change an already-running shell; with nvm, run `nvm use`. The strict engine check rejects other Node versions before verification starts.

## Editor verification

`pnpm test:browser editing` exercises Studio in Chromium, Firefox and WebKit using actual local-file navigation. The suite covers original source downloads, explicit Markdown enrichment, invalid previews, source reconciliation, imports, undo, sandbox isolation, recovery and offline exports. Screenshots are automated evidence; named assistive-technology and device acceptance require separate review.

`pnpm exec vitest run --coverage --config scripts/studio-vitest.config.js` records host-model and worker unit coverage. The editor aggregate uses unit coverage for the compiler worker and Chromium coverage for every other authored host/preview module, then applies the UI thresholds through `scripts/studio-coverage.mjs`. Generated embedded runtime data is excluded; authored error paths are retained. The same check enforces the 3 MiB gzip Studio ceiling. Production artifacts contain no source maps; verification maps are generated separately.
