# Contract implementation notes

The declarations in public-api.d.ts define the public integration surface. The owning packages implement those interfaces; successful results must contain validated values rather than partially initialized placeholders.

`Program` has a private TypeScript brand only after validation. That brand has no wire representation. `encodeProgram` yields the exact ProgramIR fields; `decodeProgram` validates unknown JSON recursively, rejects unknown keys/enum values, verifies source hash, source spans, names, types, cycles, control grids and resource limits, and recreates internal immutable indexes. A successful JSON Schema envelope alone is insufficient to brand a program. ProgramIR ABI `tinta-ir-1` must reject unsupported fields rather than evaluate them. Binary blobs or arbitrary source strings in fields are not accepted as functions.

Node IDs are assigned in preorder over the complete source AST (including hidden branches) as n000001 onward, maximum 100000. Root declarations participate in this order even when omitted from the flow tree. Column/row source spans stay in a compiler source-index side table; data row IDs use their declaration ID and original row index. Exported IR includes the spans required for diagnostics and its source. Cross-source persistence must use source hash/control signature, never a node ordinal alone.

Map/record keys are validated, stored in Map or null-prototype records and never merged into an ordinary prototype-bearing object with unsafe assignment. IR lists and table rows are immutable by contract. The decoder verifies each row's cell count and scalar types; each Row ID is unique in its source table and views reference known row IDs. Text nodes cannot carry attributes. Only the normalized Markdown element forms in DocNode exist; raw HTML is a string-valued inert node. Renderer-owned attribute dictionaries are generated from known node kinds and validated by tag-specific code, not accepted from source/IR as arbitrary trusted HTML.

`compile` is synchronous, pure, bounded and may run inside a worker. SHA-256 is a pure library function. SourceInput text must contain no unpaired surrogate code units; byte input is strict UTF-8. Result diagnostics contain warnings on success. Failure has no `value`; never attach a partially valid Program as success. `createSession` performs initial evaluation and can fail even after a successful compile if visible data-dependent domains are invalid.

`subscribe` does not invoke immediately; callers obtain the first revision with getRevision. After each non-no-op successful change it invokes each current listener once in registration order. Listener exceptions are caught by the host boundary, do not roll back an already committed engine revision, and become E_INTERNAL host diagnostics without stopping other subscribers. destroy is idempotent; subsequent session mutation calls fail E_PROTOCOL, getters return the last immutable revision, no listener is called again. A synchronous state mutation attempted from inside a notification callback fails E_PROTOCOL immediately, without evaluation or mutation. The Result<Revision> API never pretends a future queued action has committed. A host that needs another update schedules it after the callback has returned. The first initial revision is number 0, each actual committed change increments by 1.

`createSession(...,{baseline})` requires the complete valid control map; it is used for selected export answers. Reset uses that baseline. Normal editor sessions omit it and use authored defaults. Atomic source reconciliation is a host responsibility and must follow the editor contract. Pure evaluation contains no locale/date randomness; format options come only from metadata.

ReaderHost.nativeElement must be a real HTMLElement belonging to the caller's document at runtime, otherwise E_PROTOCOL. This wrapper keeps DOM types out of the portable declaration file; @tinta-lang/reader can additionally offer a browser-typed convenience overload. Mount does not modify host outside its owned child root. Each mounted instance owns one subscription and its event listeners/observers. Double-destroy is harmless.

The JSON schemas have additionalProperties:false at their defined envelopes, but their constraints do not replace semantic checks. JSON readers must detect duplicate object keys before JSON.parse would erase them. Finite-number validation is required even for an API object created in memory. The interactive program field is governed by ProgramIR, not an extension point. The expanded machine schema is generated from that closed union and must preserve round trips and unknown-key rejection; do not loosen the union to Record<string,unknown>.

Worker IDs are nonnegative safe integers; source revisions strictly increase in a document instance. A capability is at least 128 random bits encoded as hex, host generated. Strings/arrays obey language/asset limits before transfer. Never accept a message merely because it claims a matching documentId. A result for a stale revision is ignored and recorded in local debug counters, not shown as a user error. A malformed message closes its port and produces E_PROTOCOL. A compile watchdog terminates the worker; it is recreated with the same trusted bundle and no retained untrusted mutable objects.

AssetStore lookup keys are normalized source image destinations; Asset.path is the canonical hashed output path. Canonical export rebasing and neutral embedded source URIs are defined in docs/02_FILES_AND_EXPORTS.md. Returning a branded Program never authorizes ambient resource lookup.


The native editor contracts in `editor-analysis.d.ts` and `vscode-webview.d.ts` are separate from ProgramIR and the inner worker protocol. Follow `docs/13_VSCODE.md` for source verification, exact identity matching, bounded queries, canonical base64 assets, JSON validation and source-fidelity failures. An editor analysis snapshot is not a branded Program. Partial recovery cannot establish valid source. These declarations do not themselves implement the language service or authorize IO; the supplied bytes and host grants remain separate capabilities.
